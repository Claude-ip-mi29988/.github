<h3>哪些必须自己定，哪些用默认</h3>
<p>城市、ASN、会话保持这三项必须自己定，默认值几乎一定不合适。并发和带宽按号量算。协议和地区池可以先按默认，遇到兼容问题再改。</p>
<h2>二、城市与 ASN：最先定下来的两个</h2>
<p>这两项定错，后面所有参数都白调。</p>
<h3>城市跟着注册地走</h3>
<p>号的注册地填的是哪个城市，出口就尽量落在那座城市或相邻都会区。新开地区市场时，先把新市场的城市定下来，再去选线路，而不是先买一堆线再看能落哪儿。顺序反了，就会陷入「有线路但城市不对」的尴尬。</p>
<h3>ASN 看类型不看名字</h3>
<p>住宅 ASN 的持有者通常是本地宽带运营商，名字里常带 telecom、cable、fiber 这类词。移动网络 ASN 更适合手机端场景。机房 ASN 名字里常带 cloud、hosting、server。判断方式不是看名字，是查 ASN 的注册类型和地址段用途。</p>
<h2>三、会话保持与切换粒度</h2>
<p>这两个概念经常被混着说，实际是两件不同的事。</p>
<h3>两个概念别混</h3>
<p>会话保持说的是「同一个地址能用多久」，切换粒度说的是「什么时候换下一个地址」。保持时间短、切换又频繁，等于每次操作都换地方，登录状态自然不稳定。保持时间长、切换按会话来，才接近真实用户的体验。</p>
<h3>切太勤的代价</h3>
<p>很多团队以为换得越勤越安全，实际相反。短时间内出口频繁变化，在后台看就是异常行为。经验上，长期运营的号保持时间不低于 30 分钟，测品号可以短一些，但也别短于一次完整操作的时长。</p>

<h2>四、并发、带宽、协议怎么取值</h2>
<p>这三项决定你能同时干多少事。</p>
<h3>并发按峰值算，不按平均</h3>
<p>一个号日常可能只占 2 个连接，但同时开几个页面、挂个上传，峰值能到 10。按平均配，业务一忙就被限流。经验公式是号数乘 8，再留两成余量。二十个号就按 200 并发备，宁多不少。</p>
<h3>带宽按上传算</h3>
<p>多数人只看下载，实际卡住的是上传。传图、传表格这类操作对上行更敏感。单连接上行低于 5 Mbps 时，批量上传会明显排队。带宽不够的表现不是报错，是慢，很容易被误判成掉线。</p>
<h3>协议选兼容性最好的</h3>
<p>SOCKS5 兼容面广，多数客户端都支持；HTTP 代理在部分工具里配置更简单。两者都提供的服务商优先选，遇到工具不兼容时能立刻切换。</p>

<h3>留档要记哪些字段</h3>
<p>记六项就够：下单日期、城市、ASN 类型、会话保持、切换粒度、实际出口地址。后三项是排查时最常用的，务必记实际值而不是下单页面的标称值。</p>
<h3>改参数的正确次序</h3>
<p>一次只改一项，观察 24 小时。要开新市场，先建新批次，别在现有号上改城市。老号迁城是成本最高、收益最低的操作，能不做就不做。</p>
<h2>常见问答</h2>
<h3>动态线能不能当静态用？</h3>
<p>答：可以，把会话保持调到最长、切换设为按日或更久，实际体验接近静态。但地址最终仍可能变化，对地址绝对不变的场景，还是选静态线更稳。</p>
<h3>城市选错了能改吗？</h3>
<p>答：对新号直接新建批次改；对已有历史的号，不建议改。改城市等于环境整体变动，之前的稳定性积累会归零。</p>
<h3>并发买小了会怎样？</h3>
<p>答：表现为新连接排队、页面转圈、偶发超时。症状像掉线但其实是限流，加并发或错峰操作就能解决，不用换线。</p>
<h3>ASN 类型重要还是一致性重要？</h3>
<p>答：一致性更重要。同一批号用同一类 ASN，比混着用「更高级」的 ASN 更稳。类型混用会让同批次的环境差异变大，排查时更难定位。</p>
